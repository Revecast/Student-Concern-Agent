# Student Success Advisor Agent (SCA-22, SCA-23)

Employee agent (`AgentforceEmployeeAgent`) for academic advisors, written in Agent Script:
`force-app/main/default/aiAuthoringBundles/Student_Success_Advisor_Agent/`. It runs as the signed-in advisor.
Published and **active** (version 3) in jaxedupde-dev-ed on 2026-11-19.

## Topics and actions

| Topic | Actions | Notes |
|---|---|---|
| Summarize Student | `find_my_student` (flow `SUB_Find_My_Student`), `summarize_student_risk` (template `Student_Risk_Summary`) | Summary only after the gate passes |
| Draft Outreach | `find_my_student`, `draft_outreach_email` (template `Advisor_Outreach_Draft`) | Draft only; the agent has **no send action** |
| Off Topic | none | Redirects |

## Hard rules in code

- **Own students only.** The template actions are `available when @variables.student_assigned == True`. That variable
  is set only from `SUB – Find My Student`, which returns a student only when the signed-in user is the **Advisor** on
  the student's Advisee Record case team. Another advisor's student and a name nobody has get the same wording
  ("not on your caseload"), so the agent does not confirm whether a student exists. Two of the advisor's own students
  with the same name return nothing, and the agent asks for more detail.
- **Never sends.** There is no messaging action in the agent. When asked to send, it says the advisor sends the draft
  from their own email.
- **Student only.** Drafts go to the student. Requests to write to or copy a parent or anyone else are declined
  (instructions; the template also writes to the student only).

## Access

Permission set **APP – Student Success Advisor Agent** (agent access + the gate flow), in the Student Success Advisor
and Student Concern Administrator groups. Users also need an Einstein Prompt Templates licence to run the templates.

## Setup done

- Agentforce turned on: `EinsteinCopilotSettings.enableEinsteinGptCopilot = true` (reversible in Setup → Agentforce Agents).
- `BotSettings.enableBots` was **not** changed: Salesforce refused it ("Legal Terms acceptance and/or necessary feature
  dependencies required to enable Bot Settings"). The employee agent works without it. The student (service) agent
  may need it; that needs an admin to accept the terms in Setup.

## Testing

- `StudentFindMyStudentTest`: 4 tests on the gate (own student, another advisor's student, unknown name, duplicate name).
- Testing Center: **could not be created in this org.** Both test types failed with
  "Deployment failed: Not available for deploy for this organization". The spec is in
  `specs/Student_Success_Advisor_Agent-testSpec.yaml` for an org that allows it.
- Substitute: the same 6 cases as live preview conversations (`scripts/agent-tests/run_spec.py`), transcript in
  `docs/advisor-agent-test-run.md`. All 6 behaved as expected.
- Known wording risk: in one of three earlier runs, after declining to copy a parent, the agent said "reach out to them
  separately". The rule now sits in the global instructions; keep this case in the SCA-42 batch and the security review.

## Change it

Edit the `.agent` file, then `sf agent validate authoring-bundle --api-name Student_Success_Advisor_Agent`,
`sf agent publish authoring-bundle --api-name Student_Success_Advisor_Agent`, and `sf agent activate --api-name
Student_Success_Advisor_Agent`. Publishing creates a new version; `bots/` and `genAiPlannerBundles/` are generated by it.

## QA fixes (2026-11-20, PR #25)

- **Crisis Support subagent (S6-11).** When the advisor says a student may hurt themselves or others, mentions suicide or self-harm, or says a student is unsafe, the router goes to `crisis_support` first. It returns one fixed reply: 911 for immediate danger, call or text 988, contact the campus Counseling Center now. It takes no action and drafts nothing. Figures of speech about schoolwork ("this homework is killing me") are routed normally. The campus crisis number will be added when open answer 9 arrives.
- **Summary display.** The Student Risk Summary template returns numbered headings (1. to 4.). The agent shows all four headings, but the chat display shows them without the numbers.
- Tested live as agent v6: 3 crisis phrasings, 2 repeat runs of the QA crisis line, 1 false alarm, 1 parent-copy refusal, 1 summary and 1 caseload refusal. All behaved as expected.
